# mcp-hub가 대신 처리하는 것들

[English](QUIRKS.md) | **한국어**

한국 공공 API는 동작은 하지만 API마다 예상 밖의 동작이 있습니다. 에이전트가 직접 호출하면 이런 문제를 하나하나 실패하면서 알아내야 합니다. 그중 일부는 실패조차 하지 않고 **그럴듯하지만 틀린 답**을 돌려줍니다.

아래 내용은 모두 **실제 API에서 확인한 것**입니다(마지막 확인 2026-10-25). 실제 응답은 provider마다 `testdata/`에 저장해 두었고, 각 처리 방식을 테스트로 검증합니다.

상태: ✅ 처리됨 · 🚧 해당 tool이 나올 때 처리

## 에러 없이 틀린 답이 나오는 경우

가장 위험한 경우입니다. 아무것도 실패하지 않고 에이전트가 틀린 숫자를 받습니다.

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| OpenDART | 반기·분기 보고서의 손익 항목은 기간이 누적(`2025.01.01 ~ 2025.06.30`)으로 표시되지만, `thstrm_amount`에는 **최근 3개월치만** 들어 있습니다. 누적 금액은 별도 필드 `thstrm_add_amount`에 있습니다. | `current_amount`는 항상 `current_period`와 맞는 값입니다. 3개월치는 `current_quarter_amount`에 넣습니다. | ✅ |
| data.go.kr | 잘못된 파라미터를 넣어도 에러가 나지 않습니다. `DEAL_YMD=2025`(`202509`가 맞음)나 `solMonth=13`을 넣으면 **성공과 함께 결과 0건**이 와서 "데이터 없음"처럼 보입니다. | 모든 tool이 입력을 직접 검증하고, 형식이 틀리면 올바른 형식을 담아 `INVALID_ARGUMENT`를 돌려줍니다. | ✅ 공휴일 / 🚧 나머지 |
| data.go.kr (공휴일) | 데이터가 없는 연도(2004년 이전, 2년 뒤 이후)도 **성공과 함께 결과 0건**이 옵니다. 그래서 "2030년에는 공휴일이 없다"가 사실처럼 보입니다. | 연도 범위를 검사하고, 에러 메시지에 유효 범위를 알려줍니다. | ✅ |
| data.go.kr (공휴일) | "국경일" 오퍼레이션이 다섯 개 국경일이 아니라 2026년 **공휴일 22일 전체**를 돌려줍니다. "공휴일" 오퍼레이션과 결과가 같습니다. | 해당 오퍼레이션은 노출하지 않고, 공휴일은 공휴일 오퍼레이션에서만 가져옵니다. | ✅ |
| data.go.kr (아파트 실거래가) | 금액이 **만원 단위 문자열**입니다(`"84,500"`은 8억 4,500만 원). | 원 단위 정수로 바꿉니다. | 🚧 |
| data.go.kr (기업기본정보) | 이력을 보관합니다. 삼성전자 하나에 **19개 레코드**가 순서 없이 옵니다. 오래된 레코드에는 전임 대표이사가, 일부 레코드에는 시장 구분 없이 평균 급여 0이 들어 있어서, 첫 번째 레코드를 쓰면 몇 년 전 데이터가 나올 수 있습니다. | 가장 최신 레코드만 쓰고, 그 날짜를 `as_of`로 보여줍니다(2020년 이후 갱신되지 않은 회사도 있습니다). | ✅ |
| data.go.kr (기업기본정보) | 직원 수와 급여를 모르면 빈 값이 아니라 `0`이 옵니다. | `0`은 모르는 값으로 보고 생략합니다. "직원 0명"으로 보여주지 않습니다. | ✅ |
| OpenDART | 당기순이익이 같은 값으로 두 번 나옵니다(손익계산서에 한 번, 포괄손익 첫 줄에 한 번). | 완전히 같은 중복 행은 제거합니다. | ✅ |

## 다른 것처럼 보이는 에러

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| OpenDART | 에러(키 오류, 호출 한도 초과, 데이터 없음)가 **HTTP 200**과 함께 `status` 필드로 옵니다. | 표준 에러 코드로 바꾸고 원래 코드는 `upstream_code`에 남깁니다. 에러 응답은 캐싱하지 않습니다. | ✅ |
| data.go.kr | 등록되지 않은 키가 **HTTP 403**으로 와서 권한 문제처럼 보입니다. | `UNAUTHENTICATED`로 분류하고, 활용신청·Decoding 키 사용·활성화 대기를 안내하는 hint를 붙입니다. | ✅ |
| data.go.kr | 같은 에러 문서(`OpenAPI_ServiceResponse`)가 **HTTP 200**으로도 옵니다. 예를 들어 `numOfRows`가 잘못된 경우입니다. | HTTP 상태와 관계없이, XML이든 JSON이든 찾아냅니다. | ✅ |
| data.go.kr | 성공 코드가 서비스에 따라 `00` 또는 `000`이고, "데이터 없음"은 `03` 또는 `003`입니다. | 모두 통일합니다. 성공과 "데이터 없음" 모두 목록(빈 목록일 수 있음)을 돌려줍니다. | ✅ |
| data.go.kr | 승인 직후의 키는 몇 시간 동안 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`를 돌려줍니다. | hint에 이 내용을 넣어서, 에이전트가 추측하지 않고 사용자에게 기다리라고 안내하게 합니다. | ✅ |

## API마다 다른 형식

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| data.go.kr | JSON에서 결과가 1건이면 **객체**, 여러 건이면 **배열**입니다. 결과가 없으면 어떤 서비스는 `""`, 어떤 서비스는 `{"item":[]}`를 줍니다. 숫자도 필드에 따라 문자열이거나 숫자입니다(`"locdate": 20261225`). | 이런 문제가 없는 XML로 요청하고, 결과는 타입이 정해진 JSON으로 돌려줍니다. | ✅ |
| data.go.kr | XML만 주는 서비스(아파트 실거래가), JSON과 XML을 모두 주는 서비스가 섞여 있습니다. 국세청 API는 아예 다른 서버(`api.odcloud.kr`)이고 POST 요청을 받습니다. | provider 하나, 출력 형식 하나로 통일합니다. | ✅ / 🚧 |
| 전체 | 날짜가 `20251114`, `2024.12.31 현재`, `25.11.28`, `75/06/11` 등으로 옵니다. | ISO 8601(`2025-11-14`)로 바꿉니다. | ✅ OpenDART, 기업기본정보 / 🚧 나머지 |
| 전체 | 금액이 `"1,234"`, `"-"`(값 없음), `"(1,234)"`(음수) 같은 문자열로 옵니다. | 정수로 바꾸고, 값이 없으면 `null`로 둡니다(오해를 부르는 `0`을 쓰지 않습니다). | ✅ |
| data.go.kr | 빈 필드가 `""`이거나 공백 한 칸 `" "`이고, 주소에 공백이 두 칸씩 들어 있습니다. 날짜가 아닌 값도 있습니다(설립일 `99`). | 공백을 정리하고, 빈 값과 잘못된 값은 생략합니다. | ✅ |
| 전체 | 페이지 파라미터가 `pageNo`/`numOfRows`, `page_no`/`page_count`로 제각각이거나 아예 없습니다. | 입력은 항상 `page`/`page_size`, 출력은 `page_info`입니다. | ✅ |

## 없는 기능

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| OpenDART | **회사 검색이 없습니다.** 모든 호출에 8자리 `corp_code`가 필요한데, 이 코드는 약 12만 개 회사가 담긴 3.6MB zip 파일에만 있습니다. | 목록을 받아 인덱스를 만들고 매일 갱신합니다. 한글·영문 이름으로 검색하고, 띄어쓰기와 `(주)`는 무시하며, 상장사를 먼저 보여줍니다. | ✅ |
| OpenDART | 종목코드(`005930`)를 받지 않습니다. | `corp_code` 자리에 종목코드를 넣어도 됩니다. | ✅ |
| data.go.kr (기업기본정보) | 회사명 검색이 순위 없는 부분일치라서, `삼성전자`를 검색하면 37개 회사의 레코드 108개 중 `삼성전자잠실판매`가 먼저 나옵니다. `삼성 전자`나 `(주)삼성전자`로는 원하는 결과를 얻을 수 없습니다. | 검색 전에 띄어쓰기와 법인 형태를 제거하고, 회사별로 레코드를 합친 뒤, 정확히 일치하는 회사와 상장사 순으로 정렬합니다. | ✅ |
| data.go.kr (기업기본정보) | `삼성`처럼 넓은 이름은 3,158개 레코드(5.8MB)와 일치합니다. | 임의의 일부만 돌려주지 않고, 더 구체적인 이름을 쓰라는 hint와 함께 거부합니다. | ✅ |

## 연결 문제

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| OpenDART | 서버가 TLS 1.2의 RSA 키 교환 암호만 지원하는데, Go는 1.22부터 이를 기본값에서 뺐습니다. 그래서 curl은 되는데 Go 클라이언트는 `tls: handshake failure`로 실패합니다. | OpenDART에만 해당 암호를 켭니다. | ✅ |
| data.go.kr | 포털이 "Encoding"과 "Decoding" 두 가지 키를 줍니다. Encoding 키는 이미 URL 인코딩된 값이라, 대부분의 HTTP 클라이언트가 한 번 더 인코딩해서 인증에 실패합니다. | Decoding 키를 쓰라고 문서에 적었고, 에러 hint에도 같은 내용을 넣었습니다. | ✅ |

## 다른 문제를 발견하셨나요?

API 이름, 요청(키는 빼고), 응답을 담아 issue를 열어 주세요. 발견된 문제는 모두 실제 응답을 담은 테스트가 됩니다.
