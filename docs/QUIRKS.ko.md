# mcp-hub가 대신 처리하는 것들

[English](QUIRKS.md) | **한국어**

한국 공공 API는 동작은 하지만 API마다 예상 밖의 동작이 있습니다. 에이전트가 직접 호출하면 이런 문제를 하나하나 실패하면서 알아내야 합니다. 그중 일부는 실패조차 하지 않고 **그럴듯하지만 틀린 답**을 돌려줍니다.

아래 내용은 모두 **실제 API에서 확인한 것**입니다(마지막 확인 2026-10-28). 실제 응답은 provider마다 `testdata/`에 저장해 두었고, 각 처리 방식을 테스트로 검증합니다.

상태: ✅ 처리됨 · 🚧 해당 tool이 나올 때 처리

## 다른 것처럼 보이는 에러

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| OpenDART | 에러(키 오류, 호출 한도 초과, 데이터 없음)가 **HTTP 200**과 함께 `status` 필드로 옵니다. | 표준 에러 코드로 바꾸고 원래 코드는 `upstream_code`에 남깁니다. 에러 응답은 캐싱하지 않습니다. | ✅ |
| data.go.kr | 등록되지 않은 키가 **HTTP 403**으로 와서 권한 문제처럼 보입니다. | `UNAUTHENTICATED`로 분류하고, 활용신청·Decoding 키 사용·활성화 대기를 안내하는 hint를 붙입니다. | ✅ |
| data.go.kr | 같은 에러 문서(`OpenAPI_ServiceResponse`)가 **HTTP 200**으로도 옵니다. 예를 들어 `numOfRows`가 잘못된 경우입니다. | HTTP 상태와 관계없이, XML이든 JSON이든 찾아냅니다. | ✅ |
| data.go.kr | 성공 코드가 서비스에 따라 `00` 또는 `000`이고, "데이터 없음"은 `03` 또는 `003`입니다. | 모두 통일합니다. 성공과 "데이터 없음" 모두 목록(빈 목록일 수 있음)을 돌려줍니다. | ✅ |
| data.go.kr (사업자 상태조회) | "등록되지 않음"이 에러나 상태값이 아니라, `국세청에 등록되지 않은 사업자등록번호입니다.`라는 메시지로 **과세유형** 필드에 들어 있습니다. | `registered: false`로 돌려주고 과세유형은 비웁니다. | ✅ |
| data.go.kr (사업자 상태조회) | 국세청 API는 에러 형식이 따로 있고 HTTP 상태도 특이합니다. 빈 요청은 411(Length Required), 100개 초과는 413, 키 오류는 401과 `{"code":-4,...}`입니다. 게이트웨이가 가끔 504도 돌려줍니다. | 표준 에러로 바꿉니다(키 오류에는 다른 API와 같은 hint를 붙입니다). 504는 재시도합니다. | ✅ |
| data.go.kr | 승인 직후의 키는 몇 시간 동안 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`를 돌려줍니다. | hint에 이 내용을 넣어서, 에이전트가 추측하지 않고 사용자에게 기다리라고 안내하게 합니다. | ✅ |
| data.go.kr | 옛 엔드포인트(`_V2` 이전 주식시세 API)도 "없는 서비스"(12)가 아니라 **"등록되지 않은 서비스키"(30)**로 답해서, 승인된 키가 고장 난 것처럼 보입니다. | 모든 tool은 현재 API 페이지에 나온 엔드포인트를 씁니다. | ✅ |
| law.go.kr | 에러가 **HTTP 200**으로, 경우마다 다른 문서로 옵니다. OC 오류는 `<Response>`, 없는 법령은 일반 텍스트가 든 `<Law>`입니다. OC가 틀린 경우와 IP가 등록되지 않은 경우의 **메시지가 같습니다**. | 두 원인을 모두 안내하는 hint와 함께 `UNAUTHENTICATED`로, 없는 법령은 `NOT_FOUND`로 바꿉니다. | ✅ |
| law.go.kr | 시행일(`efYd`)을 정확한 시행일이 아닌 날짜로 요청하면 **빈 문서** `{}`가 오고, 없는 조문을 요청하면 조문 없는 법령 정보만 옵니다. | 법령 이력에서 버전을 고르고, 없는 조문은 `NOT_FOUND`로 돌려줍니다. 시행 예정 개정에서 생길 수 있는 조문이면 hint로 알려줍니다. | ✅ |

## API마다 다른 형식

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| data.go.kr | JSON에서 결과가 1건이면 **객체**, 여러 건이면 **배열**입니다. 결과가 없으면 어떤 서비스는 `""`, 어떤 서비스는 `{"item":[]}`를 줍니다. 숫자도 필드에 따라 문자열이거나 숫자입니다(`"locdate": 20261225`). | 이런 문제가 없는 XML로 요청하고, 결과는 타입이 정해진 JSON으로 돌려줍니다. | ✅ |
| data.go.kr | XML만 주는 서비스(아파트 실거래가), JSON과 XML을 모두 주는 서비스가 섞여 있습니다. 국세청 API는 아예 다른 서버(`api.odcloud.kr`)이고 POST 요청을 받습니다. | provider 하나, 출력 형식 하나로 통일합니다. | ✅ |
| 전체 | 날짜가 `20251114`, `2024.12.31 현재`, `25.11.28`, `75/06/11` 등으로 옵니다. | ISO 8601(`2025-11-14`)로 바꿉니다. | ✅ OpenDART, 기업기본정보 / 🚧 나머지 |

## 연결 문제

| 출처 | API의 동작 | mcp-hub의 처리 | |
|---|---|---|---|
| OpenDART | 서버가 TLS 1.2의 RSA 키 교환 암호만 지원하는데, Go는 1.22부터 이를 기본값에서 뺐습니다. 그래서 curl은 되는데 Go 클라이언트는 `tls: handshake failure`로 실패합니다. | OpenDART에만 해당 암호를 켭니다. | ✅ |
| data.go.kr | 포털이 "Encoding"과 "Decoding" 두 가지 키를 줍니다. Encoding 키는 이미 URL 인코딩된 값이라, 대부분의 HTTP 클라이언트가 한 번 더 인코딩해서 인증에 실패합니다. | Decoding 키를 쓰라고 문서에 적었고, 에러 hint에도 같은 내용을 넣었습니다. | ✅ |
